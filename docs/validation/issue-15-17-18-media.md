# Issue #17 / #18 / #15 — 媒体标识、全屏播放与图片查看

**验收构建**：`app-debug.apk`（`versionName 0.2.0`，`versionCode 2`），本地 `assembleDebug` 产出并 `adb install -r` 安装到当贝 DBD5X Pro（`192.168.10.100:5555`，1920×1080，系统 WebView `com.android.webview 66.0.3359.158`）。
**复现脚本**：`node scripts/check-media.mjs`（只读；`--shots <目录>` 可另存截图，截图含已登录时间线，不入库）
**原始证据**：`docs/validation/issue-15-17-18-samples.json`

三个工单一起做：它们改的是同一段媒体代码。#17 让人在试播之前就知道右侧是什么、确认键会做什么；#18 是确认之后的播放；#15 是确认之后的看图。分开做会把同一个入口反复重写。

## 一、改前的状态

- 媒体面板只渲染 `post.media[0]` 的一张图，没有任何标识：视频、动图、多图看起来完全一样，提示统一写「确认 查看媒体」。
- `data.js` 不解析时长。
- 查看器是一个全屏覆盖层：视频自动播放但**没有任何控制条**（没有已播时间、总时长、进度、缓冲），左右键盲定位 10 秒；图片用上下键在 1–3 倍之间缩放，**没有平移、没有边界约束、没有鼠标滚轮或拖拽**，多图切换不重置视口。

## 二、改了什么

新增 `app/src/main/assets/reader/media.js`（`TvXMedia`），把「这是什么、确认会做什么」的规则放在一处，媒体面板与查看器共用。纯 ES5。

**#17 媒体标识**
- `mark(item, index, total)`：视频给播放三角 + 「视频」+ 时长；动图给播放三角 + 「GIF」，**不给时长**（X 虽然为动图也发 `duration_millis`，但那不是可播放长度）；图片不给任何播放标记。多于一项时追加 `N / M`。
- `data.js` 解析 `video_info.duration_millis`，且只给 `type === 'video'`。缺失时长时只写「视频」，不编造。
- 标识是覆盖在封面上的独立层，封面加载失败也仍然能看出类型。
- 提示由 `prompt(item)` 给出：图片「确认 查看图片」，视频「确认 播放视频」，动图「确认 播放动图」——标识说它是 GIF，提示就不该说它是视频。
- 媒体面板可以点击，点击等同于确认，鼠标与遥控器是同一个入口。
- 媒体区获焦后左右键在多项之间走，第一项再按左键回到正文；换帖子时回到第一项。

**#18 视频播放**
- 确认直接进入全屏播放器（固定覆盖层），`object-fit: contain`，不拉伸。
- 控制条：已播时间、总时长、播放进度、缓冲进度。元素还没拿到 metadata 时用 X 给的时长顶上；元素报出 `Infinity` 或不可定位时显示「直播」并**移除进度条**，不把不可定位的媒体显示成可拖动。
- 确认播放/暂停；左右键 ±10 秒**先预览再提交**：目标时间与进度条立刻更新，按键停下 350 ms 后才真正 seek，所以连按是擦洗而不是一次一跳。进度条可点击、可拖动，拖出两端钳制。
- 播放失败后确认会**重新加载源**再播，而不是对一个已失败的元素反复调用 play()。
- 定位时进度条高亮 0.9 秒作为反馈；控制条闲置 3 秒隐藏，任何按键或鼠标动作恢复。
- 播放结束提示「确认 重播」，失败提示「确认 重试」。返回退出播放并停止媒体，回到原帖子与媒体焦点。

**#15 图片查看**
- 打开即整图适配；确认循环 `适应屏幕 → 2× → 4×`。
- 放大后方向键平移，步长取可移动范围的三分之一（至少 40px），并按图片实际布局尺寸钳制，整张图不会被拖出画面。
- 鼠标滚轮以指针所指位置为中心缩放（保持指针下的像素不动），拖拽平移。
- 适配状态下左右键切换图片并重置视口；放大状态下左右键是平移，两者不冲突。多图时另有可见的 `‹` `›` 入口，鼠标可点，放大时也能用——它们与方向键平移互不干扰，切图后视口重置。
- 放大时右上角出现小型视口示意（minimap），标出当前看的是整图的哪一块。
- 返回键先从放大恢复整图，再返回原帖子。

## 五、代码审查发现并修掉的几处

- **完全没有鼠标入口**：`.media` 上没有点击处理，查看器只能用遥控器打开——于是 #15 的所有鼠标条目都够不着。现在点击媒体面板等同于确认。
- **动图提示说自己是视频**：标识写 GIF，提示却写「播放视频」，自相矛盾。
- **定位是先提交再报告，不是预览**：改成先预览、按键停下 350 ms 再提交。
- **失败后的「确认 重试」是空承诺**：对一个已失败的元素调 `play()` 只会再次拒绝；现在会重新设置 `src` 并 `load()`。
- **多图缺少明确的上一张/下一张入口**：只有方向键和提示文字，现在补了可见可点的 `‹` `›`。

## 六、本轮未覆盖

- **动图与多图的真机实测**：脚本按「时间线上第一条符合的帖子」取样，本轮取到的是视频与单图，没有取到动图或多图帖。这两类的标识、序号与上一张/下一张由 `tests/media.spec.mjs` 确定性覆盖。
- **横图/竖图/超长图的分别验收**：真机取到的是一张 1200×622 的横图。竖图与超长图的钳制由同一段 `panLimit`（按布局尺寸计算）处理，自动化里用 4000×3000 的图验证过，但没有在真机上逐类跑过。
- **流媒体（非 MP4）**：`data.js` 只取 `video/mp4` 变体，所以「不可定位流」这条走的是元素报 `Infinity` 时的降级路径，由自动化覆盖，真机上没有可用的样例。
- **鼠标操作的真机验收**：滚轮缩放、拖拽平移、进度条拖动、点击媒体面板与 `‹` `›` 都由自动化覆盖；真机上只用了遥控器按键，没有接鼠标验证。
- **控制条闲置隐藏与缓冲进度的真机实测**：两者都有自动化覆盖，但真机脚本没有取样（闲置需要等待，缓冲取决于网络时机）。
- **「投影仪上可辨认」的依据**：只有标识字号 11.5 CSS px（设备 23 px）这一项量化证据，加上人工核对截图；截图按约定不入库，因此这条无法由仓库内的材料独立复核。
