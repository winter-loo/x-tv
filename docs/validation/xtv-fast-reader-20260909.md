# XTV 首页与详情完整内容的 5 秒优化

日期：2026-09-09。此文替代 [首轮预览优化](xtv-loading-performance-20260909.md) 的当前实现说明；首轮 21.403 秒首页、10.680 秒详情是历史基线。

## 验收口径

- 首页完整内容：从发起冷启动，到完整时间线正文排版完成并经过原生帧回调；允许明确标注更新时间的完整持久缓存。另列本次远端请求的更新耗时，二者不混用。
- 详情完整正文：从发送确认键，到目标帖完整正文排版完成并经过原生帧回调。优先复用接口已返回的完整正文，不能复用 DOM 摘要或截断正文；缺失完整正文时等待详情查询。另列本次详情／评论更新耗时。
- 时间包含 ADB 启动／按键调用开销。另记录 Activity／阅读请求起点到帧回调的 APK 内部计时，不能用较小的内部计时替换验收时间。
- `< 5.000 s` 才通过。时间线预览、加载文字、错误提示、缓存摘要均不算详情完成。完整 API 正文可复用；来源是持久缓存时，详情也标注保存时间。初始评论为服务端本页返回的评论，后续按游标分页；图片和视频下载不属于正文计时。
- 帧回调与真机截图、WebView DOM 检查配合验证，仍不是投影光学仪器的端到端测量。保留失败样本，不把单次或平均值通过当作每次通过。

## 实现与取舍

原路径要启动 Gecko 多个进程，加载 X 主文档和 React，再从 DOM 提取正文。即使修复消息揭幕，首页仍需约 20 秒。实际查询实验中，Native 可直接完成已登录的只读查询，因此将阅读从整站启动中分离：

1. 扩展只观察成功的 `HomeTimeline`／`HomeLatestTimeline`／`TweetDetail` 请求，向 APK 提供查询模板；不自动发送点赞、回复等写操作。
2. `XReadClient` 使用现有登录凭据发起 HTTPS 查询。模板由 AndroidKeyStore AES-GCM 加密保存于应用私有目录；禁止备份。日志不记录 Cookie、Authorization、正文或完整请求。账号令牌变化与退出使模板和在途请求失效。
3. 本地 `reader/` 负责阅读、评论层级、滚动、图片和视频。网络文字转义后渲染；WebView 不接触登录凭据，仅允许本地资产和 HTTPS twimg 媒体，拦截其他导航。
4. 首页完整响应以账号绑定的 AES-GCM 加密文件原子保存。每份缓存使用随机数据密钥，AndroidKeyStore 包装该密钥；账号标识在认证加密的数据内校验。下次启动优先恢复完整时间线，显示“上次时间线”与保存时间；新响应另外更新。用户已开始浏览时，新内容等待手动刷新，不抢走原帖。首次时间线请求从 Application 阶段开始，与本地界面初始化并行。GeckoRuntime 和 GeckoView 延后初始化，不参与阅读首屏。
5. 每次打开详情仍请求目标 ID 的完整数据，但不阻塞已获得的完整正文。接口中的完整长帖正文可立即复用，评论独立更新；`truncated` 摘要、缺少完整 note 文本的长帖和 Article 预览不能据此进入正文就绪。Article 查询请求 rich content，只有包含完整正文块才算完整。
6. 返回保留原列表、选择与滚动位置。取消离开的请求和排队任务，忽略过期响应。分页失败重试原游标。
7. 登录、原帖菜单、评论编辑与外链继续使用原 Gecko 适配器。用户确认后才执行原有写操作；从操作页返回会刷新当前帖状态，不丢失阅读位置。
8. 原独立详情 GeckoSession 和跨 Session 预览令牌方案已移除；Gecko 内部原帖导航使用 X 的页面内路由。

第一次登录／尚无有效查询模板时，仍由 Gecko 完成登录和会话接入；已有模板的正常阅读进入快速路径。没有实施 RFC-001 的完整 SessionController／文档代次迁移，不能将本次性能成果当作其可靠性问题已经解决。

## 实验记录

完整元数据归档见 [采样记录](xtv-fast-reader-samples.json)，阶段日志见 [实机日志](xtv-fast-reader-evidence.log)，个人时间线截图只保存在 `.scratch/loading-performance/`，不提交账号内容。

- 原有页面内导航试验：详情完整正文 3.102 秒，验证独立 Session 重启是详情等待的重要来源。
- 第一版阅读器：4 次首页 4.210–4.818 秒，4 次详情 2.024–3.006 秒。
- 扩大样本后发现首页 5.814 秒；提前请求的候选版又出现 5.559、5.666、6.549 秒，均记录为失败。
- 分段日志：本地界面约 0.7–0.9 秒就绪；上述慢样本的首页请求用时 3.719–4.775 秒。继续针对首页查询本身缩小首批数据量、排除推广内容，并移除首批请求中沿用的旧浏览记录。

缩小批量和改用 GET 的试验仍有首页超过 5 秒，因此加入完整持久缓存，明确区分“完整内容可读”与“本次查询更新完成”。这改变了实现策略，不表示远端服务的每次响应都已压到 5 秒内。最终版本连续 5 轮（每轮强制停止后启动，再打开不同帖子）：

| 场景 | 完整内容可读 | 本次网络更新完成 | 5 秒结果 |
| --- | --- | --- | --- |
| 首页冷启动 | 2.783–3.207 s，标注时间的完整缓存 | 3.823–4.780 s | 5/5 通过 |
| 详情正文 | 0.563–0.964 s，复用已完整返回的 API 正文 | 2.013–3.127 s | 5/5 通过 |

这里“通过”是这 5 轮的结果，不是所有网络条件下的保证。此前仍记录了首页更新 5.985 秒、详情更新 5.882 秒的样本；完整缓存／正文复用让阅读不再被这些更新阻塞。第一次建立缓存、缓存不可用或接口尚未提供完整正文时，仍需要实际网络返回，不能宣称这些条件一律小于 5 秒。

“首页刚出现就立即确认”的独立用例：首页完整缓存 3.219 秒，详情完整缓存正文 0.764 秒，详情本次更新 4.931 秒；后台首页更新没有抢走详情。

长正文专项：1,177 个字符（DOM `textContent.length`）的完整正文 0.778 秒可读，3.720 秒完成本次详情更新。逐字比较复用正文与详情接口随后返回的正文，结果一致，正文可滚动，首批 34 条评论可读。由其中一条评论进入其详情，正文 0.572 秒可读、本次更新 1.822 秒；返回父帖恢复相同正文与滚动位置，再返回时间线保留原帖。

投影仪上曾复现大块缓存直接经 AndroidKeyStore GCM 后恢复校验失败；没有把失败读取算作缓存命中。改为随机数据密钥加密内容、系统密钥包装数据密钥后，连续重启成功恢复。此验证不单独断言旧失败的底层原因。

## 回归与复测

设备：DBD5X Pro、Android 9 / API 28、32 位 armeabi-v7a；系统 WebView 实测 Chrome 66.0.3359.158。开发环境按 [环境基线](../../../projector-base.md)；APK 覆盖安装保留登录数据。

实机已验证普通帖、1,027 字和 1,177 字长帖、回复进入其自身详情及返回，图片显示、视频实际播放／暂停／关闭，以及原帖操作菜单、空评论编辑入口和取消。测试没有发送点赞或评论。X Article 完整正文块已设严格检测，但本次实机首页样本中尚未遇到 Article，不能将普通长帖测试当作 Article 全覆盖。

- 全量 Playwright：88 项通过；登录状态检查通过。
- Gradle `assembleDebug` / `lintDebug` 通过，lint 0 errors / 9 warnings。
- APK SHA-256：`2d2a3331492e1bb7d3acd6dd98e04f8bdc645a381ee1896b17d23b0355f207d9`。投影仪安装包哈希一致，包内 32 个阅读器／扩展资源与当前源码逐个一致。
- 扩展版本 `1.5.0`，应用版本仍为 `0.1.0`。代码基于 HEAD `d65349ce587aafdd86dec3866d2d40a7f2d762b0` 加当前工作区修改。

```sh
python3 scripts/measure-projector-loading.py cold --budget 5 --output .scratch/loading-performance/home.json
python3 scripts/measure-projector-loading.py detail --budget 5 --output .scratch/loading-performance/detail.json

    ANDROID_HOME=/home/ldd/Android/Sdk ANDROID_SDK_ROOT=/home/ldd/Android/Sdk \
    gradle --no-daemon :app:assembleDebug :app:lintDebug --offline --console=plain
```

`--require-fresh` 仍可严格要求本次网络更新在预算内完成；缓存与已取得的完整正文复用均不能通过此项。`--stop-at-readable` 在完整正文出现后返回，便于测试背景首页更新尚未结束就进入详情。

`--engine browser` 保留用于 Gecko 路径和首次会话接入测量；默认 `reader`，不会误把后台预热的 X 网页当作当前阅读画面。
