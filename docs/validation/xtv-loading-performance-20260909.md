# XTV 加载优化：首轮历史记录

日期：2026-09-09。范围：首页冷启动、时间线进入详情、详情返回。

> 此文记录 1.3.2 的首轮尝试，已被后续实现替代。当前架构和严格 5 秒验收见 [直接取数阅读器验证](xtv-fast-reader-20260909.md)。下文中的“最终包”均指首轮版本。

## 结论

详情现在可以先展示来自时间线的只读预览，再接上 X 的完整帖子与评论。慢加载不再仅因正文缺席而提示“可能已删除”。首页修复了启动时列表被输入框祖先一起隐藏的问题，但本轮尚未证明冷启动明显提速。

**本次没有实施 RFC-001 全量通信迁移。** 已观测的大段等待发生在页面请求与正文出现之前；直连 Port 不能直接消除这些耗时。RFC 中的文档身份／导航权威问题仍按原研究保留为未解决项。

## 实现

- 时间线和回复打开详情时，向扩展 Background 暂存已有帖子快照，独立 GeckoSession 通过不透明令牌领取。令牌一次消费、30 秒过期、最多保留 5 份，每份限制 200,000 个 JSON 字符；校验来源、目标路径与不同 tab。新增交接缓存仅在 Background 内存中存在。
- Native 仍使用现有 `tvx://post` 导航入口；URL 仅携带令牌，不包含帖子正文。实机发现 Android 会编码片段中的 `=`，现使用 `#tvx-preview-<uuid>`，并已验证领取成功。
- 预览明确标记为预览，复制控件不可操作，写评论等待真实正文；完整正文到达后替换预览并继承滚动位置。正文、评论分别显示加载状态。
- 正文缺席或评论先到不再推断删除。超过 25 秒显示中性重试提示；正文区域按 OK 重试，Back 可退出。服务端页面的显式不可用状态保留返回入口。
- 启动遮罩期间保持 X 待加载列表的尺寸，避免连同输入框祖先被 `display:none` 压成零高度。
- 增加有界阶段计时和实机采样脚本。日志只记录阶段、耗时与数量，不记录帖子正文、账号、URL 或令牌。
- 实机截图发现预览继承了 X 的浅色主题文字颜色，已补齐深色正文颜色及作者对齐规则。

## 测量口径与限制

冷启动从 `am start` 调用前开始；详情从发送 ADB OK 前开始。通过 Gecko RDP 采样：页面可见、DOM 遮罩撤去，并出现已聚焦的首页阅读卡片，或详情预览／真实正文。完整正文另外计时。

这些是 **DOM 就绪的采样时间，包含调试往返和主线程阻塞**，不是实体遥控器到投影光学首帧的精确测量。截图用于另外检查实际显示。网络、帖子与缓存会变化；小样本不足以推出中位数、P95 或完整加载稳定提速。

## 下一步的明确边界

首页需要继续拆分 Android／Gecko 启动、主文档首字节、X 脚本启动、时间线请求和响应后渲染。已有一次最终候选采样中，HomeTimeline 在文档起点后 7.563 秒发出，10.008 秒结束，首帖在 14.109 秒出现，14.333 秒完成首页适配，14.604 秒发出展示就绪。整体冷启动约 21.051 秒，原包约 20.454 秒，不能宣称首页提速。

最终包复测：时间线请求 7.420–10.020 秒，首帖 13.229 秒，适配 14.241 秒，展示就绪 14.407 秒。请求前等待和响应后的 DOM／适配处理都值得继续追踪。主文档 Navigation Timing 中 requestStart、responseStart、responseEnd 同为 4.350 秒，不能把注入前全部等待解释成远端服务器耗时，也不能仅凭当前阶段观测将响应后的成本全部归于 X。

优先对这些阶段做针对性优化与验证。若仍需显著降低冷启动等待，需另外设计首页内容获取／缓存呈现，明确账号隔离、过期内容和真实交互绑定；不能把旧内容冒充新时间线，也不能假定完成 RFC 的消息改造自然带来提速。
