## 行为

菜单确认喜欢或取消喜欢时，先改变本地状态、图标、计数和菜单文案，再调用原生桥提交。所有保留场景中的同帖副本一起更新；版本号保护已经在途的旧读取，仍在协调的喜欢状态也不会被新读取覆盖。

每帖保留最后确认状态、计数和最新意图。喜欢写入串行提交，重复按键合并意图；`busy` / `not_ready` 按 800、1600、3200 ms 退避，最多连续尝试四次。等待期间连按不能绕过退避。明确成功会重置暂时性失败预算；明确失败恢复最后确认状态和计数。

未知结果不当作失败，也不自动重发原提交。`ReaderHost.verify` 在独立于场景读取的请求槽执行只读核对：

- 必须拿到同帖且明确包含 `favorited` 布尔值的读取，不能把缺失字段当成未喜欢。
- 没有不同的新意图时，采用核对结果并解释完成；读取不一致也不会重发原写入。
- 核对期间用户改变意图时，先等核对结束，再根据服务端状态决定是否提交新意图。
- 核对失败最多进行四次有限退避读取，之后保留未确认状态并提示刷新。刷新可重新开始只读核对，不自动补发写入。

网络回调只更新统计和已打开菜单，不重建阅读正文、重置滚动、移动焦点或重建媒体。错误和核对提示按帖子保存，其他帖子的回调不会占用当前提示区，返回原帖后能看到解释。请求 ID 与帖子 ID 必须同时匹配，错误帖子的回调不能释放串行队列。账号切换沿用原生会话代数检查与 `FastReader.dispose()`，旧阅读器的回调不再显示。

## 真机验收

运行：`node scripts/check-like-feedback.mjs`。

脚本先替换并验证合成 `ReaderHost`，之后才发送真实遥控键事件。写入和核对由测试显式完成，不会对真实 X 帖子点赞。合成桥只存在于本轮 WebView，脚本结束会重启应用恢复正常桥接。原本本地验收使用固定数字 ID 的方式已移除：数字 ID 和作者名称不足以保证不会写入真实帖子。
