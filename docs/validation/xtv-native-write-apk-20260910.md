## 行为变化

本地阅读器的菜单仍即时打开。喜欢和取消喜欢调用 `XWriteClient`，完成后更新首页、详情和保存的阅读场景；右侧评论列表收到已发布的新评论。左下角统计仍是只读信息，不加入遥控器焦点。

写评论立即打开原生输入框。编辑末行按 ↓ 可选择发送，也可按菜单键把焦点移到发送；确认键才提交。返回保留草稿，重新打开恢复。提交中锁住发送按钮，失败保留文本；结果不明时提示先查看帖子，不自动重发。

普通状态回写不导航到原帖，也不加载原帖 DOM。显式外链、登录和原网站交互仍由 Gecko 承担。

## 实机测量

使用用户批准的测试目标及文案，通过 APK 的本地菜单和原生评论框执行；文本通过临时 UiAutomation 输入到真实 EditText，发送由 ADB 方向／确认键触发。目标是当前账号自己的帖子，未测试其他作者或受限制回复场景。

为固定目标，调试连接向阅读器提供了该目标的真实 API 返回数据；没有伪造写操作成功响应。实际写请求、确认和 UI 更新均由安装的 APK 完成。APK 未因测试加入发帖／删除的调试入口。

| 操作 | HTTP 请求与解析 | 额外状态读回 | Native 开始至结果回调 |
| --- | ---: | ---: | ---: |
| 喜欢 | 808 ms | 368 ms | 1495 ms |
| 取消喜欢 | 649 ms | 331 ms | 1286 ms |
| 文本回复 | 426 ms | 成功后另用只读探针核对 375 ms | 834 ms |

Native 总时间包含扩展元数据准备及写请求处理，不含遥控器/ADB 调度、输入评论和最后 UI 合成帧；不是光学端到端时间。每种写操作只有一个最终构建样本，不能推算 P95 或长期成功率。

回复返回后，本地详情页显示“评论已发送”，评论列表包含测试文本。独立读取再次核对正文、作者和父帖，随后仅删除新创建的测试评论：DeleteTweet 321 ms，两次读取均确认评论不存在，同时原帖仍可读。最终原帖恢复为未喜欢，测试没有遗留评论。

### 阅读速度回归

同一最终 APK 单次冷启动及随后详情测试，包含 ADB 启动／输入开销，以 Native 双帧回调观测：

| 场景 | 完整内容可读 | 本次网络更新 |
| --- | ---: | ---: |
| 首页冷启动 | 3.134 s（完整缓存） | 3.806 s |
| 首页进入详情 | 0.696 s（完整正文复用） | 2.113 s |

两个测试都以本次网络更新小于 5 秒为断言通过。样本有限，不替代无缓存、弱网或冷 Gecko 写操作的单独验收。

## 实现与故障边界

- `XReadClient` 仅向可信 Native 写入器提供现有会话快照。Cookie、Authorization、CSRF 不进入阅读 WebView。
- `write-api.js` 从当前网页模块取得 queryId、功能配置与事务标识，模块编号未硬编码。Firefox 导出回调收到的 webpack require 需要通过 `wrappedJSObject` 解包；此处已在实机修正并验证。它只准备元数据，没有写请求或 DOM 点击能力。
- Background 只转发 `writePrepare`，Native 以 UUID 对应唯一待处理结果，3 秒超时，并检查当前 Port、账号代次和 CSRF。URL、操作白名单、帖子 ID 与请求正文均由 Native 决定。
- 写请求串行，结果不明不自动重发、不切到原帖再执行一遍。回复发送前同步记录“账号 + 父帖 + 文本”摘要，成功或明确拒绝后清除；异常/未知保留，进程重启后同一回复仍会被拦截。摘要不含明文草稿。
- 回复成功必须返回新帖子、预期正文、父帖和当前账号作者。HTTP 200 但结果结构缺失、GraphQL 部分错误或网关故障均不能直接当作成功或“未执行”。
- 旧的在途详情读取不能覆盖新确认的喜欢状态或隐藏刚发出的评论。取消、迟到或重复 UI 回调不接管其他帖子的位置。
- 草稿正文只保留在当前 Activity 内存中，可跨关闭/重开评论框，不能承诺进程重启后恢复；未知回复的防重指纹独立持久化。
- 写操作仍依赖已就绪 Gecko 的当前元数据。冷启动后立即操作可能提示会话准备中；本次没有实现无需 Gecko 的原生事务标识生成，也未宣称 RFC 的文档许可／直连 Port 协议已落地。
- X 内部接口变化、真实断网/超时注入、账号切换并发、其他作者的回复限制，以及更多媒体/长文提交尚未做完整实机验收。

## 验证与清理

- 40 项 Playwright 测试：原有动作行为、阅读器写入、重复/迟到结果、保存场景更新、旧读取竞态、元数据准备及会话变化。
- 6 项 Java 单元测试：HTTP/GraphQL 成功与未知结果分类、作者匹配、目标帖子查找。
- 登录状态检查通过；`assembleDebug`、`testDebugUnitTest`、`lintDebug` 通过，lint 仍有 warnings。写入前 journal 使用同步 commit 是保证先记录再发送的有意选择。
- 实机确认原生输入框、返回保留草稿、↓ 选择发送、实际发布与界面更新、喜欢/取消喜欢，以及独立服务端读回和清理。
- 清除页面观察器和临时对象、ADB 转发、设备临时 dex；冷启动检查恢复正常时间线，测试后返回首页。
