# Issue #19 / #23 — Show more 入口与长正文按页平滑滚动

**验收构建**：`app-debug.apk`（`versionName 0.2.0`，`versionCode 2`），本地 `assembleDebug` 产出并 `adb install -r` 安装到当贝 DBD5X Pro（`192.168.10.100:5555`，1920×1080，系统 WebView `com.android.webview 66.0.3359.158`，GeckoView `155.0.20260903215306`）。
**复现脚本**：`node scripts/check-reading-flow.mjs`（只读；`--shots <目录>` 可另存截图，截图含已登录时间线，不入库）
**原始证据**：`docs/validation/issue-19-23-samples.json`

两个工单一起做：#19 让被折叠的预览说出自己是预览，#23 让展开后的正文可以按页读下去。分开做的话，#19 的「展开后能读到完整正文」会落在一个仍然翻不动的正文上。

## 一、改前的状态

- 时间线正文是 `overflow:auto`，但上下键绑在切换帖子上——长帖被**无声截断**，用户没有任何提示，也没有办法往下读。
- 详情正文按 `stage.clientHeight * 0.65` 瞬间跳动：固定屏幕比例、不看行高、没有动画、没有衔接。
- 数据被 X 截断（`complete` 为假）时，打开详情会把预览整个丢掉，只留一个「正在加载完整帖子…」的空白面板。

## 二、改了什么

**#23 按页平滑滚动**

- `pageStep(node)` 从面板自身量：`clientHeight - min(clientHeight/2, lineHeight*3)`。行高取计算样式，取不到就退回 `fontSize * 1.4`。字体或窗口变化后下一次按键重新量，不缓存。
- `pageScroll(node, direction)` 用 rAF 做 200 ms 三次方缓出动画，同一时刻只有一个动画；再按一次从**当前动画的目标**接着走，所以连按是逐页推进而不是叠加长动画。首尾按 `scrollHeight - clientHeight` 钳制。
- 重渲染时 `stopScrolling()`，并且 `saveScroll()` 记录的是动画**目标**位置——否则往返回来会落在半路的中间值上。
- 详情正文适用这一套。X Article 在阅读器里就是一段长正文，因此同样适用。**评论栏保持原来的 0.65 屏步进**：它是跟随选中项的导航，不是从头读到尾的正文；换成更大的步进会把选中的评论推出视野。自动化里断言了滚动后选中评论仍在视野内。
- 内置外链文章：内容脚本按「屏幕中央那段文字的行高 × 3 ÷ 视口高」算出重叠比例，原生侧用 `1 - 重叠` 作为 `PanZoomController.scrollBy` 的视口比例；页面没报就退回 0.28。**测量时机是 `load` 之后并在窗口尺寸变化时重算**——内容脚本以 `document_start` 注入，那一刻页面还没有布局，`elementFromPoint` 返回 null，量到的会是根字号的兜底值（实测约 0.067，翻页反而比原先更糟）。这一点是代码审查发现的，已修正。图片查看器、播放器和菜单都在按键分发的更前面，不受影响。

**#19 Show more**

- 渲染后按实际布局判断：`scrollHeight - clientHeight > 1`（真的被裁）或 `!post.complete`（X 给的就是截断文本），才在正文末尾放一个 `Show more`。短帖和已完整显示的正文不会出现无效入口。
- 入口可鼠标点击。遥控器侧：主帖的入口随帖子本身获焦，确认即进入完整阅读；长评论的入口随该条评论获焦，确认打开它。**入口本身不是独立的焦点站点**——阅读器的时间线一次只显示一条帖子，上下键用于切换帖子，在其中插入一个焦点站点会破坏这套导航。这是对「入口可以被遥控器聚焦确认」的一种取舍读法，在此明示。
- 被 X 截断的长评论现在也带同一个入口，点击或确认打开该评论的完整阅读，与主帖同一套规则。
- 数据被截断时**保留预览**并在其下标注「正在取完整正文…」，失败改为「完整正文获取失败　确认 重试」——不再把预览换成空白，也不把预览冒充成完整内容。已缓存完整正文的帖子直接展示，不重新等待。
- 返回时帖子与滚动位置照旧由 `state.bodyY` / `state.index` 恢复。

## 三、真机证据

```
preview-cut-off  marker=true   full 571  view 265  line 22.4     时间线预览确实被裁，入口出现
full-reading     marker=false  fetching=false  full 932 view 278  展开后没有残留入口
page-down        0 → 210       overlapPx 68   overlapLines 3.04   保留三行
page-up          → 0                                              上翻对称回到起点
chained-presses  → 630         oneStep 210  expected 630          三次连按 = 三步
                               reachable 654                      （或到底，取小者）
bottom           top 654       full 932  view 278                 钳制在 full - view，不越界
```

脚本还在同一帧核对了「入口是否出现」与「正文是否真的被裁」必须一致，两者不符即失败；连按一项断言的是 `min(三步, 可滚动距离)`，短文与长文都精确。

内置外链文章：真机上 `termany.sh` 报出的重叠为 **0.1307**——540 CSS 像素高的视口里约 70 px，正是该页三行文字的高度。翻页因此走 0.869 个视口，而不是任何固定比例。

## 四、本轮修掉的一个文本缺陷

真机截图里正文显示成 `Centralized roles &amp; permissions`：X 的 `full_text` 本身是 HTML 转义过的，阅读器又转义了一次。现在 `data.js` 先解码一次（`&lt; &gt; &quot; &#39; &amp;`，`&amp;` 放最后以免二次解码），渲染层仍然只转义一次。自动化断言正文里不含任何元素节点，确保没有标记泄漏进页面。

## 五、回归测试

`tests/reading-scroll.spec.mjs`（15 项）：翻页保留约三行、上下对称、步长按行高而非屏幕比例、首尾钳制、短正文不动、连按逐页衔接、评论栏同规则、查看器仍持有上键、预览被裁才出现入口、入口遥控器与鼠标都能进入完整阅读、X 截断数据显示取数状态与失败重试、已缓存完整正文无入口且不重取、返回恢复帖子与位置、正文实体解码、被截断的长评论带同一入口、评论栏滚动后选中项仍在视野内。

`tests/native-reader.spec.mjs` 两项按新契约改写：截断帖子现在保留预览并标注取数状态（原本断言空白加载屏）；滚动位置比较改为动画停稳后比较（原本是瞬时值）。

全量：Playwright 184 项通过，JVM 单测 32 项通过。七份真机脚本（#19/#23 阅读、#14 布局、#16 时间统计、#20 外链、#21 刷新、#22 前台、#13 喜欢）在本构建上重跑通过。

## 六、本轮未覆盖

- **混排图文正文的实测**：真机脚本取的是时间线上第一条被裁的帖子，没有专门挑选段落含图片的正文。#23 的「段落含图片或无法取得三行文字时…保证向前推进」由 `pageStep` 的 `Math.max(line, …)` 下限保证，并由自动化的短正文用例覆盖，但没有在真实图文混排帖上量过。
- **不同字体/行高的对比**：阅读器只有一套字体与行高，外链文章的行高由页面自报（实测一篇）。没有做多组对比。
- **外链文章翻页前后的重叠区域实测**：只验证了重叠比例被正确上报与采用（0.1307），没有在文章上逐行比对翻页前后的重叠文字。
- **遮挡工具栏的扣除**：阅读器的正文面板本身就不含表头与底部提示（它们在 `#stage` 之外），所以「扣除遮挡工具栏」在阅读器里是天然满足的；外链文章全屏显示，没有覆盖其上的工具栏。这一条没有额外实现。
