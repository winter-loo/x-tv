# 0.2.0 登录实机排查（2026-09-12）

设备：DBD5X Pro，Android 9。远端 0.2.0 试用包首次安装成功，Google 认证由使用者在设备完成。

## 复现与原因

- Google 账号选择窗口关闭后，X 仍可能暂留登录页；关闭窗口不能作为 X 登录成功的证据。
- 实机 X 根路径登录页使用 `#react-root input[name="username_or_email"]`，不含旧的登录链接或 autocomplete 标记。适配器漏判为非登录页，启动遮罩持续存在，最终显示网络超时。
- 在原页面仅补上旧识别标记并触发 DOM 更新，登录界面立即出现，确认这部分问题来自页面识别。
- 再次完成账号选择后，实机进入 `/home`，出现账号导航和真实帖子，确认 X 登录成功。
- 后续冷启动另有等待时间线的问题：X 已显示登录后导航、但帖子尚未返回。25 秒提示只能证明内容尚未显示，不能断言登录失败或网络断开。

## 修复与验证

- 增加对 X 新版内联用户名表单的识别，保留已登录导航和帖子优先规则。
- Playwright 新增真实结构回归用例：修复前失败，修复后通过；完整 reading.spec.mjs 的 11 项测试通过，独立登录状态检查通过。
- Java 单元测试、Release Lint、长期签名 Release 构建通过。
- 诊断期间临时启用 Gecko 远程调试，保留原账号数据；源码中的调试开关已恢复为 BuildConfig.DEBUG，诊断包不作为公开发行包。
- 成功打开真实帖子详情，详情与评论区域存在。没有执行点赞、关注或发帖。

公开 v0.2.0 附件未被替换；当前修复尚未作为新版本发布。实机截图仅保存在忽略目录，不提交账号信息或时间线内容。

## 最终实机结果

- 正常签名 Release 已覆盖安装，临时远程调试已关闭。
- 进入帖子详情、保存完整阅读会话后，连续三次冷启动均在 8 秒采样时显示本地时间线，不再要求认证。
- 遥控器确认：时间线→详情→全屏；返回：全屏→详情→原时间线，四个场景均截图核实。
- 本轮没有清除登录数据或重复要求用户输入密码。首次网页登录和阅读会话建立前仍可能等待较久，不能据此宣称所有网络下的首次加载已稳定。
